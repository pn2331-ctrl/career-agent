# Tracking and calibration feedback

Use this reference for local tracking, search calibration, and optional skill-improvement feedback.

## Job tracker

For each material opportunity, record only what the user authorizes:

- company, title, posting age or date, official link, source lane, and date found;
- decision and reason;
- sponsorship label and evidence location;
- selected resume path and version, if any;
- application status, next step, and follow-up date.

Do not mark a role submitted unless the user confirms it or provides reliable evidence.

## Lane-quality signals

At the end of each page, record titles reviewed, full JDs opened, recommendation counts, official-link verification rate, and rejection categories. Keep exact-title and AI-prompt signals separate.

- Low viable yield with title mismatch: review title library or filters.
- Low viable yield with responsibility mismatch: revise AI anchors.
- High relevance but low volume: preserve the lane and add an adjacent lane.
- User rejects strong-looking recommendations: revisit profile preferences before changing the query.

## Ask sparingly

Ask one short question only at a decision point:

- First page of a new lane: too broad, too narrow, or misaligned?
- Poor AI lane: continue, narrow, explore adjacent work, or pause?
- After a proposed role-family design: does this identity represent the user's intended direction and facts?
- After an evidence audit: which open gap can the user clarify first?

## Privacy-preserving improvement

Feedback stays local by default. On explicit request, create a shareable report using only opted-in aggregate metrics, selected error categories, and skill version. Exclude resume text, contact information, immigration details, raw application answers, and complete JD content unless the user explicitly chooses otherwise.

Use fictional or de-identified regression cases before changing the public skill. Test search, sponsorship labels, resume generation, and QA separately.
