# Resume QA

Use this reference after a role-family base or tailored draft exists. A score, polished prose, or keyword count never overrides a failed gate.

## Factual and evidence gate

Confirm every claim, number, tool, date, title, employer, scope, outcome, public link, and work-authorization statement against its fact state. `Confirmed` claims may be strengthened; `Source-faithful` and `Evidence-limited` claims may be retained but not expanded; `Conflict-open` claims may not be presented as active facts until the user chooses a version. Fail if a keyword has no nearby evidence, a responsibility is presented as an achievement, an unsupported skill is manufactured, or a material gap is concealed.

For every priority bullet, confirm there is a real action, decision, deliverable, workflow change, or result. Where source material supports it, ensure the reader can see ownership, operating context, method, and consequence or scale. Do not require an invented metric when the truthful proof is an artifact, stakeholder group, decision, or operational effect. If a source responsibility lacks an outcome and the user declined follow-up, preserve it rather than deleting it; do not add an outcome.

## Identity and recruiter gate

Review the rendered top third:

1. Can a recruiter name one target professional identity in ten seconds?
2. Are two independently credible proof points visible before generic content?
3. Does each priority bullet read as a real work story rather than an AI-generated keyword list?
4. Does the strongest fact appear early and retain enough specific detail to be credible?
5. Would every claim survive a detailed interview follow-up?

Fail if the title is a blended keyword label, the summary is a task inventory, the strongest evidence was compressed away, or a reader cannot see why the candidate is plausible at the requested level.

## Tailoring and lineage gate

- A tailored version uses one approved role-family base and changes only mapped, approved sections.
- The protected base remains unchanged; Company B never inherits Company A's tailored wording.
- A job with a confirmed hard failure does not receive a tailored resume.
- Unsupported JD requirements appear in the delivery note as gaps, never as resume claims.

## Artifact and ATS gate

- Read the approved `resume_layout/layout-spec.yaml`. A rendered document passes only when it matches the approved page size, margins, font family and sizes, line/paragraph spacing, section order, date alignment, bullet geometry, page count, and ATS constraints. Do not call generic document defaults a layout choice.
- Render every DOCX or PDF and inspect every page for clipping, overflow, bad wrapping, unbalanced whitespace, missing contact details, broken links, visual regression, or a visible draft/status footer. Store draft status in the path and delivery note, not in the candidate's resume page.
- If a visual reference exists, inspect the reference and output side by side. Fail `template fidelity` when the output changes its font system, heading hierarchy, alignment, information density, or page geometry without explicit approval.
- Confirm text extraction, contact links, page count, body-text readability, source-coverage disposition, skills-inventory mapping, and the user's approved format requirements.
- Confirm output path and lineage; preserve submitted and approved files.

## Delivery status

Use `DRAFT — NOT APPLICATION-READY` whenever the profile, evidence, base, JD map, factual gate, recruiter gate, or artifact gate is incomplete. For application-ready work, report: selected base; sections changed; facts checked; factual/recruiter/artifact results; and remaining material JD gaps.
